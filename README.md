# Talking Travel — вёрстка макета

Учебный проект по семантической и адаптивной вёрстке. В проекте будут две страницы макета Talking Travel: главная и статья блога. Используются только HTML и CSS.

- [Макет в Figma](https://www.figma.com/design/xC3VHAMZNq9Nm9x2TgnHei/Locofy-Sample-Project---Talking-Travel--Community-)
- Опубликованная версия: [nogod3.github.io/WebDesign1Lab](https://nogod3.github.io/WebDesign1Lab/)

## Структура проекта

- `index.html` — главная страница;
- `blog.html` — страница статьи;
- `css/style.css` — токены, базовые стили и компоненты;
- `img/` — изображения и иконки;
- `docs/decomposition.md` — декомпозиция и оценка;
- `docs/tokens.md` — словарь дизайн-токенов;
- `docs/screenshots/` — проверка на контрольных ширинах.

## Планирование

До написания разметки составлены [декомпозиция и оценка](./docs/decomposition.md), а также [словарь токенов](./docs/tokens.md). Для задач использована трёхточечная оценка PERT.

## Принятые решения

- На промежуточных ширинах колонки перестраиваются по содержимому, а не по названию устройства.
- На узком экране основная навигация раскрывается стандартным элементом `details`, поэтому программная логика не нужна.
- Длинные заголовки переносятся, фиксированная высота текстовых блоков не используется.
- Повторяющиеся цвета, интервалы и радиусы вынесены в пользовательские свойства CSS.
- Видимый фокус сохраняется для всех ссылок и кнопок.

## План и факт

| Этап | Оценка E, ч | Факт, ч | Комментарий |
|---|---:|---:|---|
| Планирование и токены | 1,4 | 1,2 | Разбор макета уложился в оценку |
| Подготовка изображений | 1,1 | 1,4 | Потребовался дополнительный отбор файлов |
| Разметка двух страниц | 1,4 | 1,1 | Общая структура переиспользована |
| Стили основных секций | 6,6 | 5,2 | Токены сократили число повторных правок |
| Адаптив и состояния | 3,5 | 2,4 | Базовые стили сразу писались для узкого экрана |
| Проверка и публикация | 3,4 | 3,1 | Исправлены замечания валидатора и сделаны снимки |

Плановый объём с резервом: **20,2 часа**. Факт: **14,4 часа**. Главной недооценённой задачей оказалась подготовка изображений, а повторное использование компонентов сократило время вёрстки.

## Проверка

Подробные результаты находятся в файле [docs/verification.md](./docs/verification.md). Выполнены следующие проверки:

- HTML обеих страниц: 0 ошибок W3C;
- CSS: 0 ошибок W3C;
- один `h1` и один `main` на каждой странице;
- все изображения имеют альтернативный текст;
- клавиатурная навигация и видимый фокус работают;
- на `360px`, `768px` и `1280px` горизонтальной прокрутки нет;
- подготовлены [контрольные снимки](./docs/screenshots/).
